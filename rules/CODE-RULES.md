# 架构与代码质量规则

本文件是 `BASE-RULES.md`「工作原则」的架构与代码质量契约, 位于规则根的 `CODE-RULES.md`. 优先级见 `ONEVOKE-AGENTS.md`「优先级」.

## 架构与边界

- 新增或改功能尽量保持既有架构, 维护模块边界, 禁循环引用和逆向引用. 必须改架构或模块边界时, 先说明影响, 由用户决策.
- 模块依赖遵循项目声明方向; 未声明则单向, 业务模块不得反向依赖基础模块具体实现. 跨模块通信只经公开 API, DTO 或事件, 禁直接访问对方内部状态, 私有存储或实现细节.
- 新共享抽象须证明至少两处稳定需求; 单点需求不提前抽象. 禁为方便穿透层级, 复制领域逻辑或建全局可变状态.
- 改公共接口, 跨模块数据模型或依赖图前, 先评估影响范围, 列受影响模块和兼容方案. 删或合并模块前, 确认无调用方, 迁移路径, 回滚风险.

## 代码质量

- 代码先保证正确, 可读, 可维护; 性能优化须有测量或明确瓶颈证据, 禁猜测式优化. 函数和类型单一职责, 命名表达业务意图, 不用含糊缩写或无意义通用名.
- 边界处校验输入, 处理空值和异常路径; 禁吞错误, 静默降级或用默认值掩盖失败. 资源, 并发, 取消须有明确所有权和生命周期, 避免泄漏, 竞态, 无界重试, 无上限队列.
- 测试覆盖改动直接影响的行为, 失败路径和回归点, 验证契约而非无关实现细节. 沿用项目既有格式化, lint, 错误处理, 日志规范, 禁无说明地禁用检查或压低告警.
- 复杂业务判断记录为何如此, 不写逐行复述注释; 临时代码须在当前任务移除或明确隔离. 性能, 日志, 错误信息禁泄露凭据, 个人数据, 内部敏感信息.
